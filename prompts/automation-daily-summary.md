# 自动化 prompt：每日总结-每日工作回顾

使用方法：复制下方正文到定时自动化的 prompt 字段，替换 `<占位符>`。频率建议：每天 16:00，RRULE 示例 `FREQ=DAILY;BYHOUR=16;BYMINUTE=0`。本 skill（work-diary）应已安装，任务中「读 skill」的步骤由其自动接管。

---

你是「每日工作总结」任务：回顾用户今天在电脑上做过什么，并顺手把可重复的活变成自动化。基础目录 `<监控根目录>/monitor/`。执行前先加载 work-diary skill，遵循其全部流程与写作规范。

1. 取数据：扫描 `monitor/logs/` 下所有日志文件，找出末尾标有「<!-- 状态：未总结 -->」的采样记录（即上次总结之后新增的）；若全库无该标记，按「当日（或最新未总结日）日志即待总结批次」兜底处理。同时按日志里记录的截屏路径抽查 `monitor/screenshots/` 下的图片，核对描述是否与截图一致（每天抽查 3–5 张，重点看打了标签的时段）。

2. 写总结：在 `monitor/reports/YYYY-MM-DD-总结.md` 生成当日报告，结构与规范按 skill 中的 report-spec 执行——一句话结论、时间线、产出物清单、AI 助手使用情况、工作主题归类、可自动化清单（值得做/观望/不建议三档）、数据缺口。语言用简体中文，先结论后过程，不堆小标题套话，不用 emoji。

3. 派生自动化：对「值得做」档里方案清晰、频次明确的条目，先列出全部现有定时任务查重，确认无同类后按 skill 的 automation-playbook 流程创建：name 以「自动发现-」开头，prompt 自包含可独立执行且不写时间安排（recurring 配 rrule、once 配 scheduledAt），创建后先按一次性试跑核对结果，通过再转周期。方案不清晰的不要建，留在报告「观望」档。

4. 语料观察：查看 `monitor/corpus/` 各语料文件的累计条数并写进报告（每次报告都要更新）。达到蒸馏阈值（默认 20 条）且尚未建过对应风格 skill 时，在报告里向用户正式提案——skill 的创建必须等用户在对话里确认，绝不自动创建。

5. 收尾：把本次已处理的采样记录末尾的「<!-- 状态：未总结 -->」改成「<!-- 状态：已总结 YYYY-MM-DD HH:MM -->」；不要删除任何日志、截图、语料或用户文件。若当天没有任何采样记录，报告里写明「今日无采样（可能为非工作时段或电脑未开机）」，不要编造内容。

6. 周一附加（仅当本次执行当天为周一时执行）：在完成当日报告之后，额外从 `monitor/logs/` 与 `monitor/reports/` 读取自【上周一】至【当天】各工作日的采样日志与每日总结，提炼出逐条不超过 20 字的工作清单，生成 `monitor/reports/工作计划表素材-YYYY-MM-DD.md`。要点：① 周六、周日无采样则不列入；② 监视体系建立前的日期若无采样数据，仅据已有痕迹标注「未证实」、不得编造内容；③ 既有自动化在执行的事项标注「（自动化）」；④ 文件末尾注明范围说明。

完成后用 5–8 行向用户汇报：今日主线、AI 助手内容概况、可疑的时间浪费点、新建了哪些自动化、语料条数、报告文件路径（若当天为周一，再附上工作计划表素材文件路径）。全程使用 `<成本约束：如 0.00x 免费倍率模型>`。
