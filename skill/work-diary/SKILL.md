# Work Diary（无感工作日记）

## Overview

把「用户每天在电脑上做了什么」变成自动积累的证据，再按时定点产出报告：

- 采集层：定时截屏 + Recent 文件痕迹 + AI 助手生成内容留档（自动化，后台只读）
- 素材层：`monitor/logs/` 按日采样日志、`monitor/corpus/` 语料库
- 总结层：每日报告 `monitor/reports/YYYY-MM-DD-总结.md`、周一素材 `工作计划表素材-YYYY-MM-DD.md`

核心原则：先结论后过程、每条结论有出处、采不到就如实写缺口、绝不编造。

## 首次部署

运行仓库根目录的 `install.py`（跨平台，幂等）：

```bash
python install.py --target /path/to/workspace
```

脚本创建 `monitor/` 目录结构、部署模板与示例文件并自检。然后按 `references/automation-playbook.md` 注册 2 个定时自动化（采样 + 总结），注册内容从 `../prompts/` 下的 prompt 文本复制。

## 日常工作流

### 每日总结（定时任务触发，约 16 点）

1. **取数据**：扫描 `monitor/logs/` 找出当日（或上次总结后新增）的采样记录；语料文件当日有无新增一并确认。
2. **抽查**：按日志里记录的截屏路径抽 3–5 张图核对描述一致性，重点核对打标签时段；不一致时在报告里更正日志并注明。
3. **写报告**：生成 `monitor/reports/YYYY-MM-DD-总结.md`，结构与写作规范见 `references/report-spec.md`。语言与用户保持一致，简体中文默认。
4. **派生自动化**：对「值得做」档中方案清晰、频次明确的条目，先查重（列出全部现有定时任务比对），无同类才创建；创建后先一次性试跑核对结果，通过再转周期。派生 prompt 必须自包含、可独立执行。方案不清晰的留在「观望」档。
5. **语料观察**：统计语料文件累计条数并写进报告。达到约定蒸馏阈值（默认 20 条）且未建过风格 skill 时，在报告里向用户正式提案；skill 创建必须等用户在对话中确认，绝不自动创建。
6. **收尾**：把已处理采样记录末尾的 `<!-- 状态：未总结 -->` 改为 `<!-- 状态：已总结 YYYY-MM-DD HH:MM -->`；不删除任何日志、截图、语料或用户文件。当天无采样时写明「今日无采样（可能为非工作时段或电脑未开机）」，不得编造。
7. **汇报**：用 5–8 行向用户汇报主线、AI 助手内容概况、时间浪费点、新建自动化、语料条数、报告路径。

### 周一附加（仅周一执行）

在当日报告完成后，额外读取上周一至当天各工作日的采样日志与每日总结，生成 `monitor/reports/工作计划表素材-YYYY-MM-DD.md`：

- 每条不超过 20 字，方便直接粘贴进工作计划表
- 周末无采样不列入；监视体系建立前/缺采样的日期仅标「未证实」，不编造
- 已有自动化在执行的事项标注「（自动化）」
- 文件末尾注明范围说明（某日无采样的原因）

## 证据与兜底规则

- **Recent 文件夹兜底**：Windows 下 `C:/Users/<user>/AppData/Roaming/Microsoft/Windows/Recent` 的 .lnk 修改时间可精确到分钟还原「打开过哪些文件」。凡用 Recent 补的段落一律标注「未采到画面，按 Recent 痕迹」，不写成已证实。macOS/Linux 替代方案见 `../docs/porting-guide.md`。
- **漏采补救**：发现某日有日志但无报告、或标记机制失效时，按「当日日志即待总结批次」兜底处理，总结后在报告「数据缺口」里提示用户核查采样任务。
- **任务职责边界**：「未转录」条目属采样任务职责，总结任务不代做，只在数据缺口提示。
- **同日多次触发**：后触发必须重新扫描当日日志，不能沿用早前「无采样」结论直接交付。
- **故障排查**：任务连续中断/漏跑时，先查自动化运行日志（502/断网类）与执行记录（模型卡死类），区分「设备没开机」与「调度失效」，结论写入报告数据缺口。

## 写作纪律

- 报告结构固定（见 `references/report-spec.md`），不堆套话、不用 emoji、先结论后过程
- 时间线含时段、程序、文件名；产出物列新建或修改的重要文件
- 主题归类按用户实际工作域定制（如合同审查/文书起草/台账统计/沟通协调/其他）
- 可自动化清单三档：值得做 / 观望 / 不建议，每条写重复频次、可省动作、建议实现方式
